# Codigo 1.1.0 - IDE Gap Closure

Release notes tecniche per la chiusura incrementale dei gap strutturali IDE.

## Obiettivo release

Completare i 4 stream del piano:
- LanguageService con integrazione runtime e fallback sicuro.
- DebugService nativo LLDB con sessione persistente e feature flag.
- Runtime estensioni allineato tra engine e IDE.
- Hardening indexing (I11, I13, I19) con benchmark pre/post ripetibile.

## Cosa cambia

### 1) Language Service
- `LanguageService` integrato nel runtime tool path per:
  - `find_references` (con fallback index),
  - `rename_symbol` (con piano semantico e fallback robusto),
  - mantenimento del contratto `find_symbol` su percorso index nativo (`kind` + fuzzy).
- Correzione parser fallback rename per output multipli:
  - `path:line: ...`
  - `path:line — symbol`
  - `path:line:column — symbol`

### 2) Debug Service
- Adapter LLDB con sessione persistente (non solo batch one-shot).
- Controlli step `in/out/over`, sync breakpoints, refresh watch/call stack.
- Feature flag introdotte:
  - `debug_service_enabled`
  - `debug_dap_lldb_enabled`
- UI DebugPanel allineata a stato/flag con fallback safe.

### 3) Extensions Runtime
- Contratto manifest unificato app/engine con compatibilità chiavi legacy:
  - `entryPoint` / `entrypoint`
  - `exposedTools` / `allowedTools`
- Validazione `minimumIDEVersion` allineata.
- Quando `exposedTools` è vuoto, runtime IDE usa whitelist derivata dalle capability.
- `PluginRuntime.clearAll()` ora effettua `unload` lifecycle su plugin caricati.

### 4) Hardening I11 / I13 / I19
- `I11`: snapshot test deduplicate card InstantGrep.
- `I13`: `IndexingTransaction` centralizzata con rollback stato/progress.
- `I19`: pipeline incremental async chunked con coerenza semantic index.
- Script benchmark pre/post:
  - `scripts/benchmark_indexing_pre_post.sh`

## Verifiche eseguite

- Test root (language/debug/extensions/tasking/provider parity): pass.
- Test `CoderEngine` (plugin/indexing/runtime regressions): pass.
- Benchmark smoke pre/post indexing: eseguito e reportabile via `docs/benchmarks/indexing-hardening/`.

## Migrazione operativa

1. Verificare e impostare feature flag runtime secondo ambiente:
   - `language_service_enabled`
   - `language_sourcekit_lsp_enabled`
   - `debug_service_enabled`
   - `debug_dap_lldb_enabled`
2. Eseguire benchmark `pre/post` prima del rollout definitivo:
   - `scripts/benchmark_indexing_pre_post.sh --phase pre --tag <ID>`
   - `scripts/benchmark_indexing_pre_post.sh --phase post --tag <ID>`
3. Allegare summary benchmark e checklist hardening alla PR/release candidate.
